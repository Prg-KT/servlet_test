DAO

JDBCを使用したデータベース操作をまとめ、 ほかの処理から分離します。

セッションを取得・生成

request.getSession()

既存のセッションを取得します。 存在しない場合は新しいセッションを生成します。

request.getSession(false)

既存のセッションがあれば取得し、 存在しない場合はnullを返します。

session.removeAttribute("name")

指定した名前の属性だけをセッションから削除します。

セッション全体を破棄

session.invalidate()

ログアウトなどで、セッション全体を無効化します。

3．重要用語集

4．試験前に必ず確認する事項

サーブレットのライフサイクル

インスタンス生成 → init() → service() → doGet()/doPost() → destroy()

init()は初期化時、 service()はリクエストごと、 destroy()は破棄時に呼び出されます。

通常、同じサーブレットインスタンスが 複数のリクエストで再利用されます。

リスナー

Webアプリケーション、セッション、 リクエスト、属性の変化などのイベントを監視します。

代表例： ServletContextListener、 HttpSessionListener、 ServletRequestListener

アノテーションで登録する場合は @WebListenerを使用します。

フィルタチェーン

行きは登録順、戻りは逆順です。

FilterA前 → FilterB前 → Servlet → FilterB後 → FilterA後

chain.doFilter(request, response)を 呼び出すと、後続のフィルタやサーブレットへ進みます。

スレッドセーフ

サーブレットのフィールドや アプリケーションスコープは、 複数リクエストから共有されます。

更新処理では競合が発生する可能性があります。

セッション管理

セッション属性は setAttribute()で保存し、 getAttribute()で取得します。

セッションIDは一般的に JSESSIONIDというCookieで管理されます。

タイムアウト時間は setMaxInactiveInterval()で設定できます。

ログイン認証

認証成功時は、ログインユーザー情報を セッションスコープへ保存します。

認証が必要なページでは、 セッションにログイン情報が存在するか確認します。

共通の認証確認にはフィルタを利用できます。

ログアウト

session.invalidate()で セッション全体を破棄します。

属性1個だけなら removeAttribute()です。

forwardとsendRedirect

forward()はサーバー内部で処理を転送します。 同じリクエストを引き継ぐことができます。

sendRedirect()はブラウザへ再アクセスを指示します。 新しいリクエストになるため、URLも変化します。

includeの違い

<jsp:include>は、 リクエスト処理時に対象のJSPを実行して取り込みます。

<%@ include %>は、 JSPの変換時にファイルの内容を取り込みます。

EL式

EL式では、スコープに保存された値や リクエストパラメータなどを簡潔に取得できます。

例： ${sessionScope.loginUser}、 ${requestScope.message}、 ${param.id}

JSTL

条件分岐には<c:if>や <c:choose>、 繰り返しには<c:forEach>を使用します。

JSTLを使用するJSPでは、 taglibディレクティブを記述します。

ResultSet

最初は行を指していないため、 next()で行を進めてから 値を取得します。

executeQueryとexecuteUpdate

executeQuery()は主に SELECTで使用し、ResultSetを返します。

executeUpdate()は主に INSERT、UPDATE、DELETEで使用し、 更新された行数を返します。

DAOパターン

DAOはデータベースへのアクセス処理をまとめ、 サーブレットやロジックから分離します。

データの参照、登録、更新、削除などを担当します。

SQLインジェクション対策

入力値をSQL文字列に直接連結せず、 PreparedStatementの プレースホルダを使います。

8．授業内容に対する正確な補足

補足1：javax と jakarta
授業資料やTomcat 9以前では javax.servletが使われることがあります。 Tomcat 10以降では基本的に jakarta.servletです。 テストでは授業で使用した環境に合わせてください。
補足2：ブラウザを閉じた場合
ブラウザを閉じるとセッションCookieが消える場合がありますが、 サーバー側のHttpSessionが直ちに削除されるとは限りません。 通常はタイムアウトまたは invalidate()で破棄されます。
補足3：アプリケーションスコープ
アプリケーションスコープに保存したデータは メモリ上のデータです。 Webアプリケーションやサーバーの再起動後も残したい場合は、 ファイルやデータベースに永続化します。
補足4：web.xmlとアノテーション
URLパターンのようにソースコードと関係が深い設定は アノテーションが便利です。 一方、運用時に変更する初期化パラメータなどは、 Javaを再コンパイルせず変更できる web.xmlが適する場合があります。
補足5：JSTLのURI
JSTLのライブラリやJakarta EEのバージョンによって、 taglibディレクティブに記述するURIが 異なる場合があります。 テストでは授業で使用した環境と記述を優先してください。
補足6：パスワードの取り扱い
実際のWebアプリケーションでは、 パスワードを平文のまま保存しません。 また、ログイン後のセッションへ パスワードそのものを保存することも避けます。
補足7：学習記録の保存場所
クイズの回答状況は、 ブラウザのlocalStorageへ保存されます。 別のブラウザや別の端末には自動的に引き継がれません。 ブラウザのデータを削除した場合も記録が消えることがあります。
